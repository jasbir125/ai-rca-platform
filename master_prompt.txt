You are a Senior AI Architect, Java/Spring Boot Architect, Cloud Architect, DevOps Engineer, and Agentic AI Engineer.

I want you to DESIGN AND IMPLEMENT a complete working Proof of Concept (POC) for an:

"AI-Powered Microservice Impact Analysis & Root Cause Analysis (RCA) Platform"

The objective is to build an enterprise-grade agentic AI platform that can investigate production incidents in a microservices application deployed on AWS EKS, correlate real-time operational data with application/architecture knowledge, identify probable root causes, determine impacted services, provide evidence and confidence scores, and recommend remediation actions.

IMPORTANT:
- Do not build a simple chatbot.
- Do not create a basic "send logs to LLM" solution.
- Build a proper Agentic AI + RAG + Tool Calling architecture.
- The AI must use tools to retrieve live operational information.
- RAG must provide application/enterprise context.
- The LLM must reason over both live evidence and retrieved contextual knowledge.
- All recommendations must be evidence-based.
- Production-changing actions must require human approval.
- The implementation must be runnable locally first and designed to deploy to AWS EKS.
- Keep the architecture modular so individual components can later be replaced with enterprise services or Publicis Sapient Slingshot capabilities.

==================================================
1. BUSINESS PROBLEM
==================================================

In a production microservices environment, engineers currently need to manually investigate incidents by checking:

- Application logs
- Metrics
- Distributed traces
- Kubernetes/EKS
- AWS CloudWatch
- Kafka
- GitLab commits
- Deployment history
- Service dependencies
- Architecture documentation
- API documentation
- Database information
- Runbooks
- Previous incidents/RCA documents

This investigation can take 30 minutes to several hours.

The platform should reduce investigation time and MTTR by automatically performing the first level of incident investigation.

Example:

Order Service starts returning HTTP 500 errors.

The AI should automatically determine:

1. What happened?
2. Which service is failing?
3. What changed recently?
4. Which downstream dependency is causing the failure?
5. Is the issue application, infrastructure, database, Kafka, network, configuration, or deployment related?
6. Which services/business flows are impacted?
7. What evidence supports the RCA?
8. What is the confidence level?
9. What remediation is recommended?
10. Was a similar incident seen previously?

LIVE DATA:

Payment latency = 700ms
Timeout = 500ms

Payment SLA < 1 second
Timeout should exceed expected latency

LIVE OPERATIONAL DATA

from

ENTERPRISE KNOWLEDGE.

- Loki
- Prometheus
- Jaeger
- EKS
- Kubernetes
- Kafka
- GitLab
- AWS

RAG provides:

- Architecture
- Runbooks
- API documentation
- Business rules
- Service SLAs
- Kafka topology
- Database knowledge
- Previous RCA

The LLM combines both.

Therefore:

LIVE DATA
    +
RAG CONTEXT
    +
AGENT TOOL RESULTS
    +
LLM REASONING
    =
EVIDENCE-BASED RCA
